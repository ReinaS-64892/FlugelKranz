# FlugelKranz

Monado / WiVRn と Linux Wayland 環境向けの、自由飛行 / 無限歩行ツールです。

## 起動

.NET 10 SDK、Linux の Wayland セッション、Monado / WiVRn のサービスと対応する OpenXR ランタイムが必要です。

```sh
dotnet restore FlugelKranz.slnx
dotnet build FlugelKranz.slnx
dotnet run --project src/FlugelKranz
```

libmonado は `XR_RUNTIME_JSON` または XDG の OpenXR runtime manifest（`~/.config/openxr/1/active_runtime.json` など）にある `MND_libmonado_path` から自動検出します。検出できない場合の既定パスは `/usr/lib/wivrn/libmonado_wivrn.so` です。`--lib-monado PATH` で明示指定できます。

起動時の引数処理は `System.CommandLine` を使用します。`--help` でオプションを確認できます。

```sh
dotnet run --project src/FlugelKranz -- --lib-monado /path/to/libmonado.so
```

OpenXR ローダー（`libopenxr_loader.so.1`）が同じ Monado / WiVRn サービスを使用するよう設定してください。必要に応じて `XR_RUNTIME_JSON=/path/to/runtime.json` を起動時に指定します。FlugelKranz はシステムのランタイム設定を変更しません。

WayVR と併用する場合は、WayVR 側の Space Drag または Space Turn が開始されると FlugelKranz 側が停止するため、WayVR 側の Space Drag と Space Turn のバインディングを外してください。

OpenXR は NuGet の [Evergine.Bindings.OpenXR](https://github.com/EvergineTeam/OpenXR.NET) を使用します。

## 操作

### 起動と共通操作

起動時は無限歩行モード（`I`）かつ ON になり、Monado / WiVRn がまだ起動していない場合も接続を待ちます。接続を試みるたびに `XR_RUNTIME_JSON` または OpenXR の active runtime manifest を再探索します。大きな `ON` / `OFF` ボタンは現在の動作状態を表し、押すと切り替わります。OFF にしても現在の位置・姿勢は保持しますが、操作中の掴みと慣性は終了します。

丸い `I` / `F` ボタンは無限歩行（Infinite Walking）と自由飛行（Free Flight）の切替、`⚙` は設定、`↻` は接続時の位置・姿勢への全体リセットです。全体リセットは ON を維持したまま直ちに位置・姿勢を戻します。ON にした後、モード切替後、全体リセット後は、押したままの操作入力を一度離してから掴み直してください。

無限歩行から自由飛行への切替は、現在の位置・姿勢を保って即時に完了します。自由飛行から無限歩行へ切り替えると、1 秒かけて接続時の高さへ戻り、接続時の姿勢を基準とする Yaw だけを残してピッチとロールを水平へ戻します。回転支点は切替開始時の片手 Turn と同じ条件（設定した HMD または有効な追跡要素の中点、同時 Drag 中は Drag の手または中点を優先）で取得し、遷移中は取り直しません。その支点の水平位置を保ったまま、接続時のオフセットで同じ物理支点を変換した高さへ、垂直な直線上を滑らかに移動させます。回転による支点の移動は並進で補正するため、大きく倒れた姿勢から戻しても落下の基準位置が横へずれません。移行中は Drag / Turn を受け付けません。

### コントローラー入力

| コントローラー | Drag | Turn |
| --- | --- | --- |
| Valve Index 左手 | トラックパッド右（内側） | トラックパッド左（外側） |
| Valve Index 右手 | トラックパッド左（内側） | トラックパッド右（外側） |
| Oculus Touch 系 | トリガーに触れながら Thumb Rest に触れる | トリガーに触れず Thumb Rest に触れる |
| Steam Frame 左手 | L1（バンパー）を押す | 十字キー上を押す |
| Steam Frame 右手 | R1（バンパー）を押す | Y（最上段）を押す |

Valve Index はトラックパッドへ触れ、指定方向へ寄せ、Force が閾値以上になったときに入力されます。既定値は位置デッドゾーン `0.30`、Force 閾値 `0.20` です。設定画面の「Valve Index 専用入力」で `0.00`～`1.00` の範囲を調整でき、検出中は左右の Force 値も確認できます。トラックパッド上には操作を割り当てていません。

Steam Frame の L1 / R1 は通常のアナログトリガーと別の `bumper/click` 入力です。Drag と Turn は同時に押せます。十字キー下・左・右、A / B、通常のトリガー、スティック、グリップには専用割当を設けません。

Steam Frame の専用割当には、接続先の Monado / WiVRn が `XR_VALVE_frame_controller_interaction` 拡張と `/interaction_profiles/valve/frame_controller_valve` プロファイルを公開し、各ボタンを転送する必要があります。拡張が列挙された場合だけ有効化してバインドします。拡張のないランタイムでも既存の Index / Touch 入力は利用できますが、Frame 固有のボタンを個別に扱えるとは限りません。Touch エミュレーションでの動作は専用割当の対象外です。SteamVR 単体は本アプリの接続先として対応していません。入力パスは [Valve の公式資料](https://partner.steamgames.com/doc/steamhardware/steamframe/input) に基づきます。Monado / WiVRn での専用プロファイルの提供状況と実機動作は未確認です。

FlugelKranz は A / B を使用しません。WiVRn + xrizer / OpenComposite を想定し、SteamVR の標準 Touch エミュレーションとは分けて扱います。確認した [WiVRn のクライアント入力変換](https://github.com/WiVRn/WiVRn/blob/75e2df579c946acf896c8a8304de931bd5b5a8d6/client/scenes/stream.cpp) と [サーバー入力実装](https://github.com/WiVRn/WiVRn/blob/75e2df579c946acf896c8a8304de931bd5b5a8d6/server/driver/wivrn_controller.cpp) では、右手 X / Y は右手 B と別入力です。左手 View も Touch のメニュー入力と別です。一方、専用プロファイルの変換表では十字キー左が Touch の Y に対応しているため、左手リセットには十字キー左を使わず View を使います。これは参照コミットのソースからの判断で、使用中の WiVRn や互換レイヤー、VRChat のカスタム割当を含む実機確認は未実施です。

Valve が説明する SteamVR の標準 Touch エミュレーションでは、右手の X / Y / B が同じ B、左手の十字キー左 / 上 / 右が同じ Y に対応します。これは上記の WiVRn の変換とは異なります。SteamVR 経由で同じ割当を使用すればゲーム操作と重複する可能性があり、FlugelKranz のバインドだけではゲーム側の重複入力を解除できません。

参照した WiVRn コミットには入力転送の不整合もあります。`map_input` は左手の `DPAD_UP` / `DPAD_LEFT` を右手として振り分けますが、対応する入力は左手に登録されており、左手の十字キー上による Turn が届くとは保証できません。実機確認では専用拡張の有無だけでなく、この入力が左手へ届くことも確認してください。このリポジトリでは WiVRn / Monado 本体を変更していません。

Valve Index / Steam Frame の長押し操作は次のとおりです。リセット用入力は Index の D-pad 下（トラックパッドの下側を通常の Drag / Turn と同じ Force 条件で押す）、Frame 左手の View、Frame 右手の X です。Frame の View / X は内部で Index の D-pad 下と同じ論理入力へ変換します。左右は別々に計時し、どちらかの入力開始から 1 秒経過した時点で両方が押されていれば、開始タイミングがずれていてもモードを切り替えます。切替に成功すると、対応しているランタイムでは左右のコントローラーへ短い振動を送ります。

| 入力 | 無限歩行モード | 自由飛行モード |
| --- | --- | --- |
| 片手のリセット用入力を 1 秒保持 | 高さリセット | 水平リセット |
| 両手のリセット用入力を 1 秒保持 | 自由飛行へ切替 | 無限歩行へ切替 |

両手保持はモード切替として扱われ、片手リセットより優先されます。コントローラーからのモード切替とモード別リセットは Valve Index と専用割当の Steam Frame に対応します。Oculus Touch 系では UI の `I` / `F` と `↻` を使用してください。

### 無限歩行モード

無限歩行では慣性を使いません。片手 Drag は、掴んだ手の上下移動だけを空間の Y 移動へそのまま反映します。両手 Drag は両手位置の中点を基準とし、上下移動量を 2 倍にします。横方向や前後方向へ手を動かしても Drag には反映しません。

Turn は常に HMD の位置を支点とする Y 軸回転です。片手 Turn は掴んだコントローラーの Yaw を打ち消し、両手 Turn はコントローラーの傾きではなく HMD の Yaw を打ち消します。片手と両手が切り替わった時点で現在の姿勢を新しい開始姿勢として採用するため、切替だけでは空間が跳びません。

片手のリセット用入力による高さリセットは、Y 位置だけを接続時の高さへ 1 秒かけて戻します。X/Z 位置と姿勢は維持します。リセット中は操作を受け付けず、完了後は入力を離して掴み直します。

無限歩行専用の **ドラグスムーズ**は、Drag、Turn、両手 Turn の追従を個別に滑らかにします。いずれも `0.0` 秒が既定値で、`0.0`～`1.0` 秒の範囲で調整できます。`0.0` 秒では補間せず直接反映し、値を大きくすると追従が緩やかになります。

**無限歩行ブースト**は、Turn 中の HMD の水平移動を進行方向へ加えて、回転時に足が後ろへ滑る感覚を補正します。補正値は追加する移動量の倍率で、既定値は `0.4`、範囲は `0.0`～`2.0` です。`0.0` では無効、`1.0` では計測した水平移動と同じ距離を追加します。

### 自由飛行モード

片手 Drag は掴んだコントローラーの位置を空間内に固定するように全軸移動し、両手 Drag は両手位置の中点を固定します。二手目が加わると、その時点の中点で掴み直すため空間は跳びません。両手 Drag から片手を離した場合は Drag 全体を終了します。残した手の入力も一度離してから掴み直してください。

片手 Turn は掴んだコントローラーの回転を打ち消すように全軸回転します。既定の回転支点は、そのフレームで有効な HMD・左右コントローラー位置の中点です。設定で HMD の位置へ変更できます。Drag と Turn を同時に使用している間は、この設定よりも Drag の手、または両手 Drag の中点を支点として優先します。

両手 Turn は Turn 開始時の両コントローラーを結ぶ直線を回転軸、両手の中点を固定した支点として、棒を掴んで回るように回転成分だけを反映します。二手目が加わったとき、または両手から片手へ戻ったときは、その時点の位置・姿勢で掴み直し、切替から角速度を生成しません。片手 Drag ともう片手の Turn は同時に使用でき、Drag の固定点を保ったままその周囲を回転できます。

両手 Drag 中は移動慣性と回転慣性の両方へドラグブレーキをかけます。片手 Drag は移動慣性だけ、Turn は回転慣性だけを止めます。操作を離すと、その時点で計測した移動速度または角速度を慣性として引き継ぎます。

片手のリセット用入力による水平リセットは、その時点で表示されている HMD の正面を最も近い水平向きへ合わせ、ピッチとロールを 1 秒かけて戻します。回転中は通常の Turn と同じ支点を固定し、同時に Drag している場合は Drag の位置を優先します。リセット中は操作を受け付けず、完了後は入力を離して掴み直します。

自由飛行モードで使う慣性パラメーターは次のとおりです。

- **慣性カットオフ**は解放速度が Drag `40 cm/s`、Turn `45 °/s` 未満なら慣性を開始しません。開始済みの慣性が減速によって閾値を下回っても停止には使用しません。チェックを外すと無効になります。
- **慣性加速倍率**は解放速度を Drag・Turn 別に `0.0`～`5.0` 倍します。既定値は Drag `1.0`、Turn `0.3` です。
- **Z加速**は参照空間オフセット適用後の HMD の正面を `Z+` として、Drag 解放時の前後成分だけを追加倍率で強めます。Turn による回転後も HMD の正面に追従します。方向との内積の絶対値を重みとするため、横方向には追加加速をかけません。範囲は `1.0`～`5.0`、既定値は `2.0` です。
- **慣性加速ブーストモード**を有効にすると、Drag 中のコントローラー移動速度がカットオフを超えている間は Drag ブレーキをかけず、解放時の加速を残っている慣性へ加算します。コントローラーが再び低速または停止するとブレーキも再開します。加算後の速度は、残っている慣性と今回の解放加速の大きい方を基準に最大倍率で制限され、既定値は有効・`4.0` 倍（`1.0`～`6.0`）です。
- **ベクトル回転倍率**は Turn で現在の移動慣性ベクトルを回す割合です。既定値 `1.0` では Turn に完全追従して曲線軌道を作り、`0.0` では回転前の進行方向を維持します。
- **慣性減速**は毎秒の指数減衰率です。`0.0` は減速なし、`10.0` は急速な減速で、既定値は `2.0 /秒` です。
- **慣性減速免除**の時間は、現在速度から実用上の停止速度まで通常減速する予測時間に対する割合です。Drag と Turn を個別に設定でき、既定値は Drag `0.20`、Turn `0.15` です。免除割合の既定値は共通の `0.90` です。
- **ドラグスムーズ**は、Drag と Turn の追従を個別に滑らかにしてトラッキングの細かな揺れを抑えます。範囲は `0.0`～`1.0` 秒、既定値は Drag `0.01` 秒、Turn `0.05` 秒です。`0.0` 秒では補間せず直接反映します。慣性速度はこの設定にかかわらず実際のコントローラー操作から計算します。
- **ドラグブレーキ**は Drag / Turn を掴み始めたときに対応する慣性を完全に減衰させます。片手 Drag は線速度、Turn は角速度、両手 Drag は線速度と角速度の両方に作用します。適用時間を `0.0`～`1.0` 秒で設定でき、既定値は `0.40` 秒、`0.0` 秒なら即時停止します。発動時は対応する慣性減速免除を解除します。

HMD のトラッキングを失った間は、ON 状態、操作状態、慣性を保持したまま空間更新を一時停止し、復帰すると再開します。手のトラッキングを失った場合、その手の操作は解除されます。両手 Turn は追跡が残る手を基準に掴み直して継続します。両手 Drag は片手を失うと全体を解除するため、残る手も入力を離してから掴み直してください。

通常のウィンドウ終了時は接続時の位置・姿勢へ復元します。強制終了やサービス切断では復元できない場合があります。他のツールが参照空間オフセットを変更した場合は安全のため停止し、その変更を上書きしません。

## 対応条件と制約

- libmonado API **1.4 以降の 1.x**。libmonado の公開 API を使用します。
- OpenXR の `XR_MND_headless` と `XR_KHR_convert_timespec_time`、STAGE / VIEW 空間が必要です。描画なしセッションを使い、VRChat からプライマリー・フォーカスを奪う操作は行いません。
- HMD・左右コントローラーは別々のトラッキング原点でも使用できます。ドライバー側でキャリブレーション済みの OpenXR 姿勢をそのまま使い、飛行の変換は `mnd_root_set_reference_space_offset` で STAGE 参照空間へ一度だけ適用します。トラッキング原点のオフセットは取得も書き換えもせず、スペースキャリブレーターや HMD 再接続によるキャリブレーション結果を入力に保持します。固定 STAGE オフセットを libmonado から読める構成が必要です。ドライバーが動的に提供する STAGE は起動時に理由を表示して操作を開始しません。
- 入力割当は Valve Index のトラックパッド、Oculus Touch 系のタッチ入力、対応拡張を公開するランタイムでの Steam Frame 専用ボタンに対応します。
- STAGE 参照空間のオフセットは、その空間を使う他の XR クライアントにも作用します。HMD・左右手が共有する原点を使うフルボディトラッカーなども同じ変換を受けます。専用の別原点は変更しません。
- VRChat 内の移動・水平線調整はアプリ側の座標変換です。本ツールはその設定を読み書きしません。

## 移動モードの実装構成

Core の実行中のモードは `MovementMode` の型で表現します。`FreeFlightManipulator` と `InfiniteWalkingManipulator` は `ManipulationMode` を継承し、オフセットの保持、論理 Drag / Turn の入力判定、解放時の処理を共通化しています。自由飛行の更新処理は、入力の変化、掴み直し、慣性、目標への追従に分けます。

移行とモード別リセットも `MovementTransition` を継承する一時的な移動モードです。補間と完了時の受け渡しは共通処理にし、移行先の型が `EnterFrom` で移行方法を決めます。`MovementSession` は選択されたモードと実行中のモードを保持し、切替・リセット・解放時に実際に適用済みのオフセットを渡します。掴み、未適用の追従目標、自由飛行の慣性は切替先へ持ち越しません。

`FlightSession` は長押し入力、設定からのモード選択、状態通知を担当し、`FlightController` はランタイム接続とワーカーの実行を管理します。`FlightMode` enum は JSON 設定と UI の識別子として残し、`MovementModes` で実装型へ変換します。新しいモードは `ManipulationMode` の派生型と必要な遷移を追加し、設定や UI に公開する際に境界の識別子・設定・表示を追加します。操作器の実行や遷移の進行処理にはモードごとの分岐を追加しません。

## 検証

```sh
dotnet test FlugelKranz.slnx
dotnet run --project src/FlugelKranz -- --diagnose --lib-monado /path/to/libmonado.so
```

Linux 再配布物は次のように作成できます。`THIRD-PARTY-NOTICES.txt` は publish 出力へ自動的に同梱されます。

```sh
dotnet publish src/FlugelKranz/FlugelKranz.csproj -c Release -r linux-x64 --self-contained false -o dist/FlugelKranz-VERSION
```

`--diagnose` は UI を開かず、接続先の一致・基準空間・HMD と両手の入力を確認します。参照空間オフセットは書き込みません。接続できても有効な入力が揃わなければ非ゼロで終了します。

自動テストは入力割当、片手・両手の切替、両モードの軸制約、回転支点、慣性、トラッキング喪失、オン・オフ、復元、UI、設定保存を対象にします。実機では VRChat を動かしたまま、Index / Touch / Frame の入力、片手・両手の切替、両モード、各回転軸、操作解放、オフ、復元、終了を確認してください。接続後にスペースキャリブレーターで片方のドライバー空間の向きを変更した場合も、変更後の見えている手の動きと Drag / Turn の方向が一致することを確認してください。自動テストだけではランタイム・コントローラー・VRChat の組み合わせを保証できません。

Steam Frame はランタイムの専用拡張と各入力の転送を確認した上で、L1 / R1 の Drag、十字キー上 / Y の Turn、Drag + Turn の同時押し、View または X の片手長押しによる両モードのリセット、View + X の両手長押しによるモード切替と振動を確認してください。押し続けてもモード切替が反復しないこと、操作後に離して掴み直せること、A / B・通常のトリガー・未割当の十字キーで FlugelKranz が反応しないこと、飛行操作で VRChat 側の A / B やメニュー操作が発生しないことも確認してください。

## 座標変換

操作器の物理座標系は **Monado ルート座標系**です。ドライバー空間のキャリブレーションを適用した機器姿勢を `Qᵢ`、接続時の STAGE からルートへの変換を `S₀`、本ツールの飛行変換を `D` とします。`D` の初期値と復元先は恒等変換です。トラッキング原点のオフセットや機器ごとの原点 ID は取得せず、外部ツールによるキャリブレーションは `Qᵢ` に反映された状態で使用します。

飛行の適用先は STAGE のみで、`S = D⁻¹ × S₀` とします。OpenXR が報告する姿勢は `Pᵢ = S⁻¹ × Qᵢ` なので、入力を `S × Pᵢ = Qᵢ` として復元します。積は右側を先に適用します。この復元では STAGE と本ツールの飛行変換だけを取り除き、ドライバー空間のキャリブレーションは打ち消しません。表示側では `Pᵢ = S₀⁻¹ × D × Qᵢ` となり、すべての機器に同じ飛行変換が一度だけ作用します。

`mnd_root_set_reference_space_offset` は OpenXR の参照空間変更イベントを発生させるため、入力クライアントは既存の空間ハンドルを保持したままイベントを処理します。原点更新や再接続でキャリブレーションが変わっても、その結果を含む姿勢で処理を継続します。外部ツールによる STAGE オフセットの同時変更への追従・調停は行いません。

自由飛行の Drag は選択した手、または両手の物理座標の中点を固定します。Turn は開始時の選択手姿勢に現在姿勢の逆回転を合成し、片手では全軸、両手ではコントローラー間の軸へ拘束します。並進は有効な追跡要素の中点、頭、または同時 Drag の固定点が動かないように補正し、Drag と Turn を動かし続けても固定点を維持します。無限歩行では同じ物理座標から Y 並進だけを抽出し、Turn は片手のコントローラーまたは両手時の HMD から Y 回転だけを抽出します。VRChat 世界と飛行者の軸への対応は、VRChat 側の水平線調整などを合成した結果になります。

無限歩行への遷移は、物理座標の支点を `p`、開始時の操作オフセットを `O₀ = (R₀, t₀)`、接続時の飛行オフセット（恒等変換）を `Oᵦ` として計算します。Monado ルート内の開始支点は `a₀ = O₀(p)`、着地点は `a₁ = (a₀.X, Oᵦ(p).Y, a₀.Z)` です。1 秒の smoothstep で支点を `a(u)` へ垂直補間し、姿勢を `R(u)` へ補間した後、並進を `t(u) = a(u) − R(u)p` として求めます。これにより `O(u)(p) = a(u)` が成立し、回転を先に適用してから並進する順序でも支点の X/Z を維持します。ルートの Y 軸を基準とする下降であり、VRChat 世界や飛行者のローカル軸への対応は VRChat 側の設定との合成によります。
